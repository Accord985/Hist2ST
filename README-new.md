# Hist2ST: Onboarding and Experiments

Hist2ST explores predicting spatial gene expression from H&E tissue images. The onboarding notebooks prepare aligned HEST breast data, extract image features, and evaluate a ridge-regression baseline. The experiment notebooks document alternate workflows and model comparisons.

## Notebook groups

### Onboarding

Run these notebooks in order. They are designed for a new member with basic Python and CSE background.

1. [01 ? Data preparation](notebooks/organized/01_data_preparation.ipynb): inspect HEST metadata and paired image/expression data, then create aligned breast-cohort files.
2. [02 ? GenBio embeddings](notebooks/organized/02_genbio_embeddings.ipynb): turn each spot patch into a 4,608-value GenBio-PathFM embedding.
3. [03 ? PCA, ridge, and evaluation](notebooks/organized/03_pca_ridge_evaluation.ipynb): compare spot-, slide-, and patient-level evaluation and reproduce the full-cohort ridge result.

The three-patient run is a pipeline check. The full-cohort patient-level result is the replication endpoint.

### Experiments

Each notebook introduces code blocks by their role in the workflow and shows recorded results where available.

- [Cohort filtering and split](notebooks/organized/exp_cohort_filtering_and_split.ipynb): alternate HEST filtering and sample-level splitting.
- [PCA versus no PCA](notebooks/organized/exp_pca_vs_no_pca.ipynb): random-spot comparison and spatial-block follow-up.
- [Neighborhood MLP](notebooks/organized/exp_neighborhood_mlp.ipynb): patient-fold spatial context experiment.
- [Transformer preparation and training](notebooks/organized/exp_transformer_preparation_and_training.ipynb): optional full pipeline from cohort preparation to transformer training.

## Environment and setup

Python 3.11 is recommended. A virtual environment keeps the project packages separate:

```powershell
uv venv --python 3.11
.venv\Scripts\Activate.ps1
```

For ordinary notebooks, the first setup cell installs that notebook's dependencies. If a notebook imports reusable project code from `src/`, it uses the repository dependency list:

```powershell
pip install -r requirements.txt
```

### Hugging Face access

Create a Hugging Face account, accept the access terms for the HEST dataset and GenBio-PathFM model, and create a read token. Choose one sign-in method:

- **Private `.env` or environment variable:** set `HF_TOKEN` in your local environment. A `.env` file can be loaded with `python-dotenv` or exported by your shell. Keep `.env` private and out of Git; never put a real token in `.env.example`.
- **Enter the token manually:** use `getpass.getpass()` and pass the result to `huggingface_hub.login(token=token)`. The input is hidden and the token should not be saved in a notebook cell.
- **Interactive login:** run `from huggingface_hub import login` followed by `login()`, then enter the token in the prompt.

### Check CPU and GPU availability

In PowerShell or a terminal, run:

```powershell
nvidia-smi
```

This reports whether an NVIDIA GPU and driver are visible and shows the driver?s supported CUDA level. If the command is unavailable or no GPU is listed, use CPU PyTorch. `nvidia-smi` checks the system; it does not tell you whether the active Python environment has a CUDA-enabled PyTorch installation.

Check PyTorch from the notebook kernel:

```python
import torch
print("PyTorch:", torch.__version__)
print("CUDA available to PyTorch:", torch.cuda.is_available())
print("GPU:", torch.cuda.get_device_name(0) if torch.cuda.is_available() else "CPU")
```

Install PyTorch and torchvision using the [official PyTorch installation selector](https://pytorch.org/get-started/locally/). Select your operating system, Pip, Python, and either **CPU** or the CUDA option that matches the machine. Run the command generated by the selector; avoid hard-coding a CUDA wheel because the supported build depends on the driver and Python environment. In Colab, select a GPU runtime for Notebook 02 and check `torch.cuda.is_available()` after installation.

## Data storage

The team?s current shared location is Google Drive under `BDD_BJMJ/HEST_breast_ST`. Shared Drive storage lets teammates reuse the same downloads and embeddings. You may instead use a local directory or a Google Drive Desktop mirrored folder. Set `HIST2ST_DATA_DIR` to the desired path before starting Jupyter, or edit `DATA_DIR` in each onboarding notebook. Use the same directory for Notebooks 01?03.

For Colab, mount Google Drive and point `DATA_DIR` to the shared folder. For local runs, ensure the directory has enough free space; raw patch archives can be large. Do not commit downloaded data, model weights, credentials, or patient-sensitive information.

## Reproduce the ridge baseline

1. Confirm HEST access and choose a writable data directory.
2. Run Notebook 01 with `N_PATIENTS = 3`. Check barcode alignment and the spatial expression map. Then set `N_PATIENTS = None` to prepare the full study.
3. Run Notebook 02 and confirm one 4,608-feature row per spot in matching barcode order.
4. Run Notebook 03 with the full cohort and four patient folds. The result directory contains fold assignments, score tables, settings, and figures.
5. Treat patient-level scores as the main generalization estimate. Spot and slide splits are comparisons that can share nearby tissue or patients across train and test.

Saved notebook metrics are historical run results. The spatial-block PCA follow-up has no saved numeric result yet; rerun it before drawing conclusions.
